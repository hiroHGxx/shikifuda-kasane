## 2. ボイス導入（本作の主題）

12場面の台詞を入れた。段が新しい御霊に替わったときに、その御霊が**名乗る**。

- 出どころは2系統: **Irodori-TTS**（無料ローカル・公式配布wavを参照音声に）と **ElevenLabs**（公式指定Voice ID）
- **公式指定Voice IDが現行ElevenLabsから削除されていた**（ネム=Aria／ネコマタ=Charlotte）→ 公式配布ボイスから代役を立てた
- 「頁」の読みが崩壊する（イーラーショー／ユーポー）等の読み間違いに時間を取られた。**最終的な解は「カタカナで書く」「そもそもその語を選ばない」**

工程で得たものは [VOICE.md](VOICE.md) に**「次に作るときの手順書」**として全面的に書き直してある。
6手順（台詞設計 → 声選び → 生成 → 読み上げ検証 → 後処理 → 実機で通し聴き）＋音量の設計＋つまずき集。
**以後ボイスを作るときはまずこれを読む。**

### 音量とダッキング

ボイスを載せたあと、琴と木魚が台詞とほぼ同じ大きさで鳴っていて名乗りの頭が埋もれていた。
`src/game.js` のコメント「BGMは控えめに、効果音を主役にする」はボイス追加前の判断で、
**ボイスを足したときにSE側を見直していなかった**という取りこぼし。

SEを一律に下げず、**台詞を `voiceBus` に分離して鳴っている間だけ `sfxBus` を約-7dB沈める**方式にした。
琴は浄化の唯一の報酬フィードバックで、8回の台詞のために痩せさせるのは割に合わないため。
数値と実測は [VOICE.md「音量の設計」](VOICE.md#音量の設計)。

## 3. 自動検証パイプライン（`scripts/playtest.js`）

80段までの通し確認を人力でやるのは無理なので、自動化した。
サーバー起動 → 3ルート検証（満月成就／夜明け／稽古が記録を残さないこと）→ スクショまで面倒を見る。

```bash
npm i --no-save puppeteer-core   # 初回のみ
node scripts/playtest.js         # → /tmp/kasane-*.png・全✅で exit 0
```

ここで分かった重要な制約:

- **Chrome の `--virtual-time-budget` では rAF 駆動のゲームループが進まない。**
  「一瞬で長時間ぶんを進める」目論見は外れ、0段のまま撮れてしまう
- 正解は **puppeteer-core で実時間待ち**。`page.waitForFunction()` で終了条件を待ち、
  `page.evaluate()` でDOMの値を吸い出してから screenshot
- **タブがバックグラウンドでも rAF は止まる**ので、実ブラウザのタブで放置検証もできない
- `#autotest` は「ぴったりの位置に来たら置く」ので80段到達まで実時間で約79秒かかる。
  夜明け側は `#autocut`（わざと40pxずらす）で数段で終わらせる

**デバッグ用の自動プレイhashを最初から仕込んであったのが効いた。**

## 5. 踏んだところ

- **Artifact の CSP は `fetch("data:")` をブロックする。**単一HTML化した音源data URIを `fetch()` で読むと
  Artifact 上で全滅する。`atob()` で直接 ArrayBuffer 化 → `decodeAudioData` が正解。
  **合成音のフォールバックがあると「鳴っているのに実は読めていない」事故が静かに起きる**
  （1作目のArtifact版も琴が合成音のままだったと、これで気づいた）
- **稽古モードのロゴ3タップは `click` ではなく `pointerdown` で数える。**
  iOSのダブルタップズーム抑止（touchendの `preventDefault`）が2回目以降の click を打ち消すため
- **公式ちびアイコンへの差し替え**（08-24）: `get_spirit` の sheets に顔アイコン（透過・1024²・栞含む全キャラ）が
  追加されていた。札絵の切り抜きより軽く綺麗で、`faces.js` が 544KB→198KB になった。
  **公式素材は増えることがあるので、更新時に台帳を見直す**
- **80段の演出から咲耶のカットインを撤去**（08-24）。「余韻1.3秒 → 栞の満願のページ → 栞の声」に整理した。
  Artifact版が 13.1MB → 10.9MB に軽くなった副次効果も大きい

## 8. 【2026-08-30】御霊おとしの更新を移す（第1便）— 文字コード・ズームの出口・セーブ保全

御霊おとしが08-28〜29の健診と更新で得たものを、こちらへ順に移す。下調べは
`kitan-circle/data/articles/20260830-1200-kasane-port-diff.json`（14項目）。
本便は「1行で済む事故予防」「実害のある5行」「セーブ保全」の3つ。

### `dist/artifact.html` に文字コードの宣言が無かった（未爆の地雷）

- **症状**: 出ていなかった。ブラウザの推測がたまたま当たっていただけ
- **原因**: `scripts/build-dist.js` の `inlineScripts` のあと、head から
  `<meta[^>]*>` をまとめて剥がしている。**charset ごと落ちる**。非ASCIIを含む
  `<title>式札かさね</title>` が先頭に来る構造と噛み合うと、ブラウザが文字コードを推測する
- **向こうで起きたこと**: 御霊おとしは同じ作りで **IBM866（キリル文字）と誤推測**され、
  08-29に全文字化け＋横はみ出しを起こした。**`file://` でも起きる**。
  **こわいのは、中身が変わると推測結果も変わること。**長らく偶然うまくいっていて、
  ボイスを足してファイルが変わった日に転んだ
- **直し方**: 書き出しの先頭に `<meta charset="utf-8">` を必ず戻す（非ASCIIの `<title>` より前）
- **確かめ方**: `file://` で `document.characterSet` が `UTF-8`・`<h1>` と `.game-title` が
  読める文字・`scrollWidth === clientWidth`（横はみ出しなし）・`pageerror` 0

### `gesturestart` を無条件に塞いでいた（ズームの出口が無い）

- **原因**: ダブルタップ抑止は `touchend` の350ms判定でやっているのに、`gesturestart` は
  無条件に `preventDefault` していた。**入口だけでなく、戻すためのピンチまでこちらが塞いでいた**。
  本作は稽古モードがタイトルロゴの3連打なので、ズームを踏む機会がむしろ多い
- **直し方**: 等倍のときだけ抑止する（`visualViewport.scale <= 1.01`）
- **確かめ方**: `visualViewport` を差し替えて `gesturestart` を投げ、`defaultPrevented` を見る

| scale | 1.0 | 1.01 | 1.5 | 3 | visualViewport 無し | 0 | NaN |
|---|---|---|---|---|---|---|---|
| 抑止する | ○ | ○ | **×（通す）** | **×（通す）** | ○ | ○ | ○ |

### わいわいの枠の中では記録が保持されない（`waiwai.save` へ移行）

仕様は SPEC §7-a。実装の型は御霊おとし `docs/DEVELOPMENT.md` §11-B をほぼそのまま移した。
**本作は御霊図鑑を持たないので、束は4値**（`best` / `title` / `titleRank` / `sound`）。

移すにあたって本作固有だった点が2つ。

- **`best` は1段ごとに `localStorage` へ書いていた。**御霊おとしは夜の終わりに1回だけ書く型だが、
  そのまま移すと**夜の途中でアプリを畳まれたときに最高段が消える**（従来は残っていた）。
  親フレームへの postMessage を毎段投げるのも筋が悪いので、`saveDirty` の旗を立てておき、
  **`visibilitychange`→hidden と `pagehide` で未書き込みがあれば書く**ことにした。
  実機で「終了させられる直前」に確実に来る最後の機会がそこ
- **音の好みは、タイトルの2択（音あり／静かに入る）が必ず上書きする。**束には載せるが、
  遊びの見え方は変わらない。遅れて届いた記録が選択を覆さないよう `soundChosen` の旗を置いた
  （御霊おとしと同じ）。**この移植で振る舞いを変えないことが目的**

#### 確かめた（`#autocut` は数段で夜明けになるので短時間で「残る」を測れる）

| 経路 | `waiwai.mode` | 保存先 | 残った | もう一夜 |
|---|---|---|---|---|
| ①ローカル配信（Pages相当・SDKあり） | standalone | `waiwai:fudakasane_save` | 8 → 8 ○ | ○ |
| ②`sdk.js` を落とした状態 | （SDKなし） | 旧キー4つ | 8 → 8 ○ | ○ |
| ③`dist/artifact.html` 素のまま `file://` | standalone | `waiwai:fudakasane_save` | 8 → 8 ○ | ○ |
| ④`dist/artifact.html` に Artifact 相当のCSP | （SDKなし） | 旧キー4つ | 8 → 8 ○ | ○ |

4経路とも `pageerror` 0。②④では `console.warn` が残る（**黙って落ちない**）。
④の `console.error` はCSPの拒否2件だけ（フォントと `sdk.js`。どちらもArtifactでは想定内）。

- **移行**: 旧キー4つだけを置いて開く → 束が
  `{"best":57,"title":"月導の架け手","titleRank":56,"sound":"off"}` になり、**旧キー4つが消え**、
  HUD最高 57・誉れ「月導の架け手」
- **大きいほうを採る**: 手元 12／わいわい側 72 → 72 が残り、称号も titleRank の大きい側

#### タウンの中（bridged）は stub でしか確かめていない

SDK が親として認めるのは `https://waiwai.town` / `localhost:8787` / `127.0.0.1:8787` の3つだけ
（`ALLOWED_PARENT_ORIGINS`）。**127.0.0.1:8787 に親ページの stub を立て**、ゲームを iframe に入れて
`hello-ack` / `save` / `load` を親の localStorage で中継した。
**これは筋が通ることの確認であって、本番の確認ではない。**

- `waiwai.mode` が `bridged` になり、記録は**親側**に入り、**iframe 自身の localStorage は空のまま**
  （＝守りたかった性質そのもの）。親ごと開き直すと HUD最高 8・誉れが戻る
- 親の返事を 600ms 遅らせても同じ（カードが出た時点で値は入っている）
- **親の返事が 1800ms（握手＋読みで計3.6秒）／`load` に返事をしない**とき: 2500msで切って warn 2行、
  **親側は空のまま**（＝読めていないので書かない、が効いている）。その夜は旧キーに書いて記録を落とさない

## 9. 【2026-08-30】御霊おとしの更新を移す（第2便）— 全国ランキングと番付

仕様は SPEC §7-b。実装の型は御霊おとし `docs/DEVELOPMENT.md` §10・§12 をそのまま移した。
本作固有だったのは**スコアの設計**と**送ってはいけない経路**の2つ。

### 80段が上限なので、段だけでは番付にならない

御霊おとしは得点に上限が無く同点問題が起きなかった。本作は **80段でクリア＝到達者が全員同点**になる。
企画の裁定（`kitan-circle/data/articles/20260830-1700-kasane-ranking-score-ruling.json`）は
**合成値 `段 * 100 + 浄化の通算`**。

- **後付けの別軸ではない。**ずれれば札が細り、ぴったり重ねれば幅が戻る——浄化は最初から勝敗を左右している
- **桁は構造で守られている**（浄化 ≦ 段 ≦ 80 < 100）ので、段が1つ違えば浄化では逆転しない
- **`getTopScores` は meta を返さない**（御霊おとし第12便で本番実測）。番付に浄化を出すには、
  score 単体から復元できる合成値であることが要る
- `purifyTotal` を新設した。既存の `streak` は連続数で、ずれると0に戻るので通算には使えない

### 自動プレイのハッシュが本番の番付を汚す（本作固有の落とし穴）

**`#autotest` / `#autocut` / `#autowobble` は稽古モードではなく、本番ルールで動く。**
記録を守る既存のガードは `!practice` だけなので、そのままでは
**検証を1回回すたびに理論最大値 8080 が本番の `main` ボードへ載る**。PV撮影の `#autowobble` も同じ。

- 送信条件を `canSubmitScore() = !practice && !autotest && !autocut && !autowobble` の1か所にまとめた
- `autotest` / `autowobble` の宣言はファイル末尾（ループの節）にあったので、状態の節へ前倒しした
- **`scripts/playtest.js` に4つ目の検証を足した**: stub の `waiwai` を置いて、3ルートすべてで
  `submitScore` の呼び出しが**0回**であることを毎回数える。ガードは書いたら終わりではなく、
  次に誰かが自動プレイの口を足したときに気づける形にしておく

### 結果カードが背の低い画面で溢れた（この変更で作り込んだ回帰）

  文字は12pxの床を割らない＝**縮めてよいのは余白だけ**

  @media (max-height: 700px) {
    #overlay .card { padding-top: 18px; padding-bottom: 18px; gap: 8px; }

  **横を詰めてある**ので、一括で書くと横の余白まで押し戻す（`#overlay .card` のほうが詳細度で勝つので、
  書いた順に関係なく上書きされる）
