## 制作環境

### Irodori-TTS（無料・ローカル）
- 導入先: `kitan-circle/kitan-works/tools/Irodori-TTS`（uv・MPS動作。1本4〜8秒）
- 実行例:
```bash
export PATH="$HOME/.local/bin:$PATH"
uv run --no-sync python infer.py --hf-checkpoint Aratako/Irodori-TTS-v4.1-Small \
  --text "台詞" --ref-wav <公式配布wav> --caption "<公式の声質説明文>" \
  --model-device mps --codec-device mps --seed 42 --output-wav out.wav
```
- 公式配布wav: `https://vibe.co.jp/luna-occulta/media/voice/<id>_sample.wav`（24キャラ分）
- **参照音声の話速を強く引き継ぐ**。caption で「速く」と書いても変わらない。
  テンポを変えたいときは**参照音声そのものを別キャラに差し替える**のが唯一有効だった

### ElevenLabs（無料プラン）
- キー: `~/.secrets/elevenlabs.env`
- **無料プランは API からライブラリボイスを使えない**（402 paid_plan_required）。
  ブラウザUI（Claude in Chrome で自動操作）からのみ利用可能
- 公式指定 Voice ID: 於兎=Lola `mHX7OoPk2G45VMAuinIt` / 紫苑=Rose `8PfKHL4nZToWC3pbz9U9` / 栞=Mini `hO2yZ8lxM3axUxL8OeKX`
- ネム=Aria `9BWtsMINqrJLrRacOk9x` / ネコマタ=Charlotte `XB0fDUnXU5powFXDhCwa` は
  **現行 ElevenLabs から削除済みで新規アカウントでは使用不可** → 公式配布ボイスから代役を立てた
- モデルは Eleven v3。推奨タグを台詞の先頭に付ける（例 `[japanese][calm][mysterious]`）
- 生成の設定は履歴タブに残る。同じキャラを後から追加収録するとき、入力（タグ込み）を復元して条件を揃えられる
- 同名ボイスの取り違えを防ぐため、UI の「声のIDをコピー」→ `pbpaste` で Voice ID を照合してから回す

## 次に作るときの手順

式札かさねで遠回りした分を、順番の形に直したもの。**1と2で決まる分が大きく、
3以降の作業量はそこで決まってしまう**というのが今回いちばん強く感じたこと。

### 1. 台詞を設計する

生成で戦う前に、戦わなくていい台詞にしておく。

- 公式MCP `kitan-lore` の `get_spirit` で口調（voice.tone / samples / firstPerson / address）を取ってから書く
- **単語・掛け声で書かない。必ず文にする。** 「それっ！」は指示語の抑揚になる（つまずき#3）。
  一言の文脈があるだけで、AI がその発声の意味を取れるようになる
- **数字・常用外漢字・外来語を設計段階で避ける。** 「八十段」「頁」で沼ったのは、
  そもそもその語を選んだ時点で決まっていた（#2 #5）
- 尺は 3.4 秒を目安に。後処理の早回しは 1.35 倍が上限なので、それを超える長さは縮まない

### 2. 声を選ぶ

**ここが一番効く工程。**「演技が伸びるか」「ノイズが乗るか」は声側の収録・整音品質で
おおむね決まっていて、後工程の努力では取り返せない。式札かさねでは公式指定 Voice ID の
あるキャラは選ぶ余地がなかったが、指定ボイスが廃止されていたネム・ネコマタは選べた。
そこに時間をかけるべきだった。

本番台詞を回す前に、候補を並べて**試しセリフ**を流す。

1. **最初に見るのはノイズの無さとクリアさ。**演技力の判定はその次
2. 次に、そのキャラが実際に言いそうな台詞を2〜3パターン。棒読みになる声はここで分かる
3. 決めたら**1キャラ＝1音源に固定**（#4）。途中で出どころを変えると別人に聞こえる

Irodori の場合、「声を選ぶ」＝「参照 wav を選ぶ」。参照 wav は声質だけでなく**話速まで支配する**ので、
選んだ時点でそのキャラの喋る速さも決まる。

### 3. 生成する

- **表記の直し方の優先順**: ①カタカナにする（外来語は確実） → ②助詞を足して読みを一意にする
  （字自体を読めていない場合には効かない） → ③別の漢字に当て替える。
  三点リーダは使わず、間は読点で作る（#1）
- **話速は生成側で粘らない。** 速くしたいときは普通の速さで生成して、後処理の `atempo` で上げる。
  遅くしたいときだけ読点「、、、」を重ねる。Irodori は caption に速さを書いても効かない
- **タグは効かないテイクが出るのが普通**（ElevenLabs v3）。公式推奨タグを先頭に置き、
  さらに乗せたい感情があれば英語で書く。1回で効かなくても書き方が悪いとは限らない
- **テイクは必ず複数引く。**子音の立ち上がりはテイクごとに揺れる（#6）

### 4. 読み上げを検証する

生成後は必ず音声認識で読み上げ内容を確認する。

```bash
export PATH="$HOME/.local/bin:$PATH"
cd kitan-circle/kitan-works/tools/Irodori-TTS
uv run --no-sync python -c "
from transformers import pipeline
asr = pipeline('automatic-speech-recognition', model='openai/whisper-small', device='mps')
print(asr('/tmp/x.wav', generate_kwargs={'language':'japanese','task':'transcribe'})['text'])
"
```

- 漢字の変換揺れは認識側の癖なので、**読み（音）が合っているか**で判断する
- `whisper-large-v3-turbo` は **MPS で壊れた出力を返す**（「イ.」「!」等）。
  使うなら `device='cpu', torch_dtype=torch.float32`。短い音声なら CPU でも十分速い
- **ASR は「読みの崩壊」の検出には使えるが、微妙な子音の判定は当てにならない。**
  採否は必ず人の耳で決める。聴かせるときは、後処理を通した本番と同じ形にしてから聴く

### 5. 後処理で揃える

`scripts/trim-voice.py` が実装。無音・余韻をトリムし、長さを詰め、フェードで閉じて正規化する。

```
発声区間検出（10ms RMS包絡・ピーク比6%）→ atempo（上限1.35）→ フェードアウト0.12s → 音量正規化
```

出力は 24kHz mono wav・ピーク 0.88。長さは 3.4 秒を**目標**とするが、
早回しの上限（1.35倍）で届かないものはそのまま通す（実測の最長は栞の満願 4.44 秒）。

末尾のフェードアウトは、生成ボイスにありがちな「語尾がブツッと切れる」を消すための処理。
数値としては 0.12 秒とごく短いが、あるとないとで印象がはっきり変わる。

### 6. 実機に載せて、通しで聴く

**素材の段階で OK でも、ゲームに載せて BGM・SE と重なった状態で聴くまで疑う。**
Whisper での検証は素材への検査であって、聴こえ方の検査ではない。

- イヤホンで通す。スピーカーでは聞こえないノイズがある
- 見るのは3つ ―― 声だけ浮いていないか / SE に埋もれていないか / キャラ間で大きさが揃っているか
- 式札かさねは 8 段ごとに声が鳴るので、80 段を通せば全キャラ分を一度に確認できる

## 音量の設計

原則は**「聴かせたい順に大きい」**。声がいちばん上、次に効果音、BGM がいちばん下。
一般的な動画制作でも「BGM は声より 20dB ほど下」という目安が使われる。

### 式札かさねの実測

素材のピークと `src/game.js` の再生ゲインから計算した、出力段での理論ピーク。

| 音 | 素材ピーク | ゲイン | 出力ピーク |
|---|---|---|---|
| 台詞 | -1.1 dBFS | `1.0` × sfxBus `0.9` | **約 -2.0 dBFS** |
| 琴（ぴったり浄化の主音） | -1.0 dBFS | `0.95` × 揺らぎ0.92〜1.08 × sfxBus `0.9` | **約 -3.1〜-1.7 dBFS** |
| 木魚（合成・札を置く） | — | `0.8`（斬りは `0.6`） × sfxBus `0.9` | 約 -2.9 dBFS 以下 |
| BGM | -1.7 dBFS | `volume 0.16` | **約 -17.6 dBFS** |

### 所見

**BGM は原則どおり十分下がっている（声との差 約 15.6dB）。ずれているのは SE で、
声とほぼ同じ大きさで並んでいる。**設計上は声が SE より数 dB 上に立つべきところ。

`src/game.js` のコメント「BGM は控えめに、効果音を主役にする」はボイスを載せる前の判断で、
ボイス追加時に SE 側を見直していなかった。段替わりの台詞は 3.4 秒前後鳴り続ける一方、
その間もプレイヤーは札を置き続けるので、木魚と琴は**高い頻度で台詞に重なる**。
特に 8 段ごとの `sfxMilestone` の琴（減衰 1.6 秒）は、その 450ms 後に始まる名乗りの
**頭 1.3 秒**――いちばん聞かせたいところ――に必ずかぶる。

### 対処：一律に下げず、台詞の間だけ沈める（ダッキング）

SE を一律に下げる案は採らなかった。琴はぴったり浄化の唯一の報酬フィードバックで、
80 段ぶんの手応えの中心にある。8 回の台詞のためにそれを痩せさせるのは割に合わない。

実装は `src/game.js`。台詞を `sfxBus` から外して専用の `voiceBus` に流し、
台詞が鳴っている間だけ `sfxBus` を沈める。

```
SFX_BUS = 0.9    効果音バスの素の大きさ
SFX_DUCK = 0.45  台詞中の倍率（約 -7dB）
沈む: setTargetAtTime(tau=0.05)     → 0.15秒でほぼ底
戻す: setTargetAtTime(tau=0.12)     → 台詞の終わり0.2秒前から。終了時点で -1dB、0.5秒後に復帰
```

台詞そのものの大きさは据え置き（旧 `gain 1.0 × sfxBus 0.9` = 新 `gain 1.0 × voiceBus 0.9`）。
台詞が重なった場合は `duckUntil` で長いほうの終わりに合わせる。

これで通常プレイの琴は素のまま、名乗りの間だけ声と SE に 7dB の差がつく。

## つまずいた点と対処（重要）

1. **「……」が「てんてん点」と読まれる**（ElevenLabs）
   → 三点リーダを使わず、句読点だけで間を作る

2. **漢字の読み間違い**「第一夜」→いちい、「八十段」→ぱちじゅう
   → ひらがなで書くと読みは直るが**イントネーションが崩れる**。
   助詞を足して読みを一意にするのが正解（第一**の**夜 / 八十**の**段）。
   最終的には数字を使わない台詞に変更した

3. **単語だけの掛け声はイントネーションが破綻する**
   → 「それっ！」が指示語の抑揚になる等。**文にすると自然になる**。
   これが「掛け声」→「登場の台詞」へ設計変更した理由

4. **1キャラで声の出どころが混在すると別人に聞こえる**
   → 1キャラ＝1音源に統一すること

5. **常用外の漢字は読みが崩壊する**「頁」→ イーラーショー／ユーポー（ElevenLabs）
   → 同じ字でも文ごとに違う音を当ててくるので、崩れ方から原因を推測しない。
   外来語は**カタカナで書く**のが確実（「頁」→「ページ」）。#2 のように助詞で読みを
   一意にする手は、そもそも字を読めていない場合には効かない

6. **カタカナ語でも子音の立ち上がりが弱いことがある**
   → 「ページ」が Whisper に「ていじ／提示」と認識される個体差あり。
   テイクごとに揺れるので**複数テイク引いて耳で選ぶ**。ASR は崩壊の検出には使えるが、
   微妙な子音の判定は当てにならない（採否は必ず人の耳で決める）

7. **AI ボイスの棒読みは、テクニックではゼロにできない**
   → 声選び（手順2）と表記・タグの工夫でかなり減らせるが、現行の道具では限界がある。
   道具の限界として受け入れて、限界の内側で最善を尽くす、という構えで臨む

## ボイス帖（試聴ページ）

`assets/audio/voice_*.wav` から単一HTMLを組み立てる。台詞・話者・五行色・声の出どころは
`scripts/build-voice-page.js` の `LINES` が正本（本書の表と対応）。

```bash
node scripts/build-voice-page.js   # → dist/voice-book.html（約2.7MB）
```

- 公開先: Claude Artifact `c7500fd9-fb59-4d3e-8c13-91108370e2a6`
- ゲーム本体と同じ公式トンマナ・トークン（宵闇に金）と Shippori Mincho B1 を使用
- 再生はゲームと同じ `atob()` → `decodeAudioData`。**`<audio src="data:">` や `fetch(data:)` は Artifact の CSP で鳴らない**
