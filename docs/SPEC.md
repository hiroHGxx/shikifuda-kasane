# 式札かさね 仕様書

『月蝕綺譚 -Luna Occulta-』二次創作の積み上げパズル。御霊おとしに続く第2弾。
本書は 2026-08-21 時点の実装仕様。

## 1. ゲーム概要

- ジャンル: Stack式（積み上げ）パズル。等角投影（2.5D）
- プラットフォーム: モバイルブラウザ優先の Web（PC も可）
- 遊び方: 宵闇を往き来する式札をタップでとどめて重ねる。ずれた分は夜に喰われて札が細り、空振りで夜明け（ゲームオーバー）
- 世界観: 月が蝕まれる夜、あるじどのが式札を重ねて「喰われた月への道を架ける」。第一夜の召喚描写（月へ呼びかける）に接続
- ビジュアル: 公式トンマナ「宵闇に金」（御霊おとしと共通トークン）

## 2. 盤面・物理

- 論理座標 480×720。等角投影 ISO_X=0.86 / ISO_Y=0.5、CX=240、BASE_Y=560
- 札: footprint F0=190（正方形）、厚み TH=30
- 交互に X軸・Z軸方向へスライド（本家準拠）。速度 `min(170 + 段*4.2, 460)`
- ぴったり判定 PERFECT_TOL=7px。**5連続以上のぴったりで幅が+6px回復**（本家準拠・入れすぎ注意）
- ずれ: 欠けた分は破片として落下（絵柄も一緒に欠ける）
- カメラ: `floors*TH - 300` を追従（lerp 6/秒）

## 3. 御霊の階梯（段位）

8段ごとに交代。**最初は明るい餡音**（眠たげなネムでは開幕が締まらないため）。

| 段 | 御霊 | 五行色 |
|---|---|---|
| 1–8 | 餡音 | 木緑 #6FB069 |
| 9–16 | 於兎 | 土琥珀 #C08A3E |
| 17–24 | ネム | 水青 #5FB4D9 |
| 25–32 | ネコマタ | 金白金 #C6BFA8 |
| 33–40 | 弁天 | 水青 #5FB4D9 |
| 41–48 | 宇迦 | 火紅 #E0562F |
| 49–56 | イズナ | 金白金 #C6BFA8 |
| 57–64 | 紫苑 | 木緑 #6FB069 |
| 65–71 | 咲耶 | 火紅 #E0562F |
| 72– | **栞**（MOON_ZONE） | 金泥 #F0CE7E |

- 札の天面にその御霊の札絵を敷く（上2枚のみ描画。顔が中央上寄りに来るよう上端の正方形を使用）
- 72段からは金縁の「栞の段」。鈴が約2.6秒おきに鳴る
- **80段（MOON_FLOOR）で満月成就＝クリア**。ここで一夜は終わる（札は出ず、入力も止まる）
  - 満月成就の余韻（1.3秒）→ 栞の満願のページ（クリア画面）→ ページが開いた直後に栞の台詞
  - クリア画面は夜明けと同じ `#overlay` を出し分ける。`#result-card.clear` で金泥の縁・栞の札絵・満願の言葉を出す

## 4. 演出

- **帳（とばり）**: 開始時、黒緞子の扉が閉じた状態で現れ → 栞の台詞 → 拍子木とともに左右へ開く（1.5s）。合わせ目の金襴帯は自作SVG（花紋＋蔓唐草の繰り返し。公式素材は不使用）
- 背景: 夜空グラデ＋星（固定位置・瞬き）＋昇る金の塵＋ビネット
- 月: 最高到達段に応じて満ちる（80段で満月）。満月成就後は脈動
- ぴったり: 金の粒バースト＋天面の環＋「浄化 ×n」
- 夜明け（空振り）: 結果画面は蝕紅の見出し＋到達した御霊の札絵
- 称号: 到達段で11種（宵の口→…→月白の頂→満月成就）。80段が上限なのでそれ以上の称号は置かない。最高記録は localStorage 永続

## 5. 音

- BGM: 公式配布キャラソング「Freehand」（ネムのテーマ）。音量0.16・ループ
- 琴: 御霊おとしと共通の実サンプル（G3 196.5Hz を変速で陰旋法に展開）。**ぴったり浄化は琴の音のみ**
- 拍子木・鈴・削げ音: WebAudio 合成
- **台詞（12場面）**: 帳が開くとき（栞）／各御霊の登場時（8段ごと）／72段（栞）／満願（栞）
  - 詳細は `docs/VOICE.md`
- **台詞・琴はページ読み込み時から先読み**（Pages版のみ）。開幕の栞の台詞は開始+0.35秒で鳴るため、開始クリック時に取り始めると初回訪問で間に合わない。dataURI版（Artifact）は復号が即時なので遅延のまま
- ミュートは BGM に加えて再生中の台詞も止める。台詞中は効果音を約-7dB沈める（ダッキング。`docs/VOICE.md`「音量の設計」）

## 6. 稽古モード（裏モード）

- タイトルの「式札かさね」を**1.5秒以内に3回タップ**で起動。「稽古（札が欠けない）」と表示
- 札が細らず、空振りしてもゲームオーバーにならない。80段までの演出・台詞を通しで確認するため
- **BEST・称号は保存しない**（稽古の到達を本番の誉れに混ぜない）
- **実装上の注意**: `click` ではなく `pointerdown` で数える。iOSのダブルタップズーム抑止（touchend の preventDefault）が2回目以降の click を打ち消すため
- `#autotest`（自動でぴったり）、`#autocut`（わざと40pxずらす）、`#autowobble`（本番ルールでわざと少しずらし、中くらいの細さを保って積む。PV素材用）もデバッグ用に残置

## 7. 入力・iOS対策

- pointerdown で札を置く。開始・リトライ直後は700ms入力を受けない（ボタンのタップの名残で即ミスするのを防ぐ）
- ダブルタップズーム抑止（350ms以内の2回目を preventDefault・ボタン除外）
- **`gesturestart` は等倍のときだけ抑止する**（`visualViewport.scale <= 1.01`）。無条件に塞ぐと、一度ズームしたあと元へ戻すピンチまで塞がれて出口が無くなる（御霊おとしで実機報告あり）。`visualViewport` が無い環境・`scale` が 0/NaN の環境は従来どおり常に抑止

## 7-a. わいわいSDK（セーブ保全）

`https://waiwai.town/sdk.js` を1行読み込む（**`crossorigin="anonymous"` を省略しない**。COEP下で黙ってブロックされる）。仕様の正本は https://waiwai.town/llms.txt 。

**大原則: SDKが無くても・読めなくても・応答しなくても、ゲームは一切変化なく遊べること。**
`dist/artifact.html` は Artifact の CSP で外部スクリプトが止まるため、これは想定内の常態である。
すべての呼び出しは `waiwaiTry()`（try/catch ＋ 自前タイムアウト `SAVE_TIMEOUT_MS = 2500`）を通す。
SDK 自身はハンドシェイク2秒＋要求5秒待つので、素直に `await` すると画面が最大7秒止まる。
**失敗は握りつぶさず `console.warn` を1行残す。**

- **わいわいタウンの枠（iframe）では、ゲーム自身の localStorage が保持されない**（御霊おとしで2026-08-29にオーナーの iPhone で実機確認。Safari・Chrome とも、タブとアプリを終了すると記録が消えた。**Pages を直接開いた場合は消えない**）
- 4つの値を**1キー `fudakasane_save` の束**にまとめ、`waiwai.save()` / `waiwai.load()` を主経路にする（`best` / `title` / `titleRank` / `sound`）
- **移行**: 初回に旧 localStorage キー（`fudakasane_best` ほか4つ）を読み、あれば束にして保存してから旧キーを消す（公式の推奨手順）。**消すのは保存が解決してから**
- **`best` / `titleRank` は大きいほうを採る**（`mergeSave()`）。移行と自己修復が同じ規則で片づく。`best` は 0〜`MOON_FLOOR`(80) に丸める
- **タイムアウトと「記録が無い（`null`）」を区別する。**潰すと「読めなかった」を「初回だ」と誤読し、**空の値で向こうの記録を上書きする**。`waiwaiTry` は `{ok, value}` で返し、`ok:false` の夜は SDK に書かない
- チラつき対策は「**待たせる**」に寄せる。タイトルのカードの表示自体を `saveLoaded` まで待たせる（0段を出してから差し替える見え方にしない）。`#autotest` 等の自動プレイも同じく待つ。**5秒の保険だけは無条件**
- 書き込みは**夜の終わり（`showGameOver`）に1回**。`best` と称号は `saveData` を書き換えるだけにして、最後に `persistSave()` を1回・await しない。**あわせて画面を離れるとき（`visibilitychange`→hidden・`pagehide`）にも未書き込みがあれば書く**——従来は1段ごとに `localStorage` へ書いていたので、夜の途中で閉じても最高段が残っていた。その保証を落とさないため
- タウンの外では SDK が自動で localStorage 保存にフォールバックする＝**同じビルドをそのまま配布できる**
- 稽古モードの到達は従来どおり記録に残さない（`!practice` のガードは `best` と称号の両方に入っている）

## 7-b. 全国ランキング・番付

**送るスコアは合成値 `段 * 100 + その夜の浄化の通算`**（2026-08-30 企画裁定）。
本作は80段が上限で、**段だけでは到達者が全員同点**になる。そこで、この遊びが最初から測っている
「ぴったり重ねる」＝浄化を従の軸に畳む。

- **桁は構造で守られている**: 浄化回数 ≦ 段数 ≦ 80 < 100（1枚置くごとに浄化は最大1回）。
  段が1つ違えば浄化では絶対に逆転しない。理論最大 8080
- 復元は `段 = floor(score/100)` / `浄化 = score % 100`。**`getTopScores` は meta を返さない**ので、
  番付に浄化を出すには合成値であることが要る
- `purifyTotal` は通算（`streak` は連続数で、ずれると0に戻るので別に数える）。`restart()` で0に戻す
- 結果カードの自分の表示は従来どおり「63段」。合成値は見せない
- ボードは **`main`**（初回送信で自動作成）。**浄化の仕様（`PERFECT_TOL`・幅回復の規則）を変えたら `main_v2` へ**
- 受理上限（`max_score`）は設定しない。名前の入力欄も作らない＝匿名は「ナナシ」
- 順位は `submitScore` の応答の `rank` を正本にする。`getMyScore` は保険。総数と上位の顔ぶれは
  **同じ1回の `getTopScores(board, 10)`** で取る（押してから取りにいかない）
- `endGame` 相当（`showGameOver`）で送る。**await しない**＝カードも「もう一夜」も待たせない
- 夜の通し番号 `nightId` を `restart()` で増やし、遅れて返った前の夜の順位が次の夜のカードに出るのを塞ぐ
- **取れなければ行ごと出さない**（「取得できませんでした」も出さない）。上位の顔ぶれが取れなかった夜は
  順位の行を `<button>` ではなく `<span>` で組む＝番付への入口ごと存在しない
- 番付は結果カードの順位の行から開く。閉じ方は ✕ と外側タップの2つだけ。名前は他人が入れた文字列なので
  **`textContent` だけで置き、20字で切る**。自分の行は金泥の縁＋地。上位10人の中に居ればその行に印を付け、
  居なければ ⋮ を挟んで下に1行足す（二重に出さない）
- **送ってはいけない経路**: 稽古（`practice`）に加えて、**自動プレイのハッシュ
  （`#autotest` / `#autotest-sound` / `#autocut` / `#autowobble`）は稽古ではなく本番ルールで動く**。
  塞がないと検証やPV撮影のたびに本番の番付が汚れる（`#autotest` は全段ぴったり＝理論最大値）。
  ガードは `canSubmitScore()` の1か所にまとめてある。`scripts/playtest.js` が送信0回を毎回数える
- 順位の2行でカードの背が伸びるため、`@media (max-height: 700px)` で**縦の余白だけ**を詰める
  （横は既存の `max-width: 430px` の指定を壊さないよう、一括の `padding` で書かない）

## 8. アセットとビルド

- 札絵: 御霊おとしから流用（公式素材蔵ランク10）。**栞のみ公式正典シートを参照にLovartで生成**（`fuda_shiori.jpg`）
- ビルド: `node scripts/build-dist.js` → index.html（Pages用・単一ファイル）／ dist/artifact.html（全埋め込み・約13.5MB）
- **重要**: Artifact の CSP は `fetch(data:)` をブロックする。音源は `atob()` で直接 ArrayBuffer 化して decodeAudioData すること（fetch を使うと Artifact 上で全滅する）

## 9. 検証

80段までの通し確認は、実時間で自動プレイさせて撮るのが確実。`scripts/playtest.js` が
サーバー起動〜3ルートの検証（満月成就／夜明け／稽古が記録を残さないこと）〜スクショまで面倒を見る。

```bash
npm i --no-save puppeteer-core       # 初回のみ
node scripts/playtest.js             # → /tmp/kasane-*.png・全✅で exit 0
```

- `#autotest` は「ぴったりの位置に来たら置く」ので**80段到達まで実時間で約79秒**かかる
- **Chrome の `--virtual-time-budget` では進まない**（rAF 駆動のゲームループが仮想時間で回らず、0段のまま撮れてしまう）。puppeteer で実時間待ちにすること。**タブがバックグラウンドでも rAF が止まる**ので、実ブラウザのタブで放置検証もできない
- 夜明け側の確認は `#autocut`（わざと40pxずらすので数段で終わる）
