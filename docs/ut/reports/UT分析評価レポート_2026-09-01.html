12シナリオ中、受入NGが2件・摩擦ありが2件。NG 2件は同じ一つの仕組みから出ている——札は台から270px外に現れて台へ進入してくるのに、入力の解禁がそれより早い。帳が消えた直後（約0.5秒）と「もう一夜」の直後（0.7〜1.3秒）に押すと、札は必ず台の外にあって空振り＝0段の夜明けになる（10/10・5/5 で再現、窓の外なら 20/20 で置ける）。しかもこの作品は0段の夜も全国番付へ score 0 を送る（stub と本物 SDK の standalone で確認。宵あらわしは「0柱の夜は送らない」と決めている）。つまりいちばん急いで押した初見の人ほど、最初の夜が0段で終わり、その0が全国の番付に載る。本番ボード（09-01）に 0 の行はまだ無いが、載る筋は開いている。

D. 根本課題

R-1. 札が台に着く前に、指が解禁される

確信度: high — 独立した3系統の証拠が一致: 時刻別のタップ試行（+3300/3500 不可・+3700/3900 可、再開後 +800〜1200 不可・+1400 可）、コマ撮り（+3300／+3450 で札が台の外、+3600 で重なり始め）、コード（newSlab() が top ± (F0+80) に出し、place() は pausedUntil だけを見る）。再現 10/10・5/5・20/20。

因果連鎖: 札は台から270px外に現れ170px/sで進入する → 入力の解禁（帳 3150ms／再開 700ms）が札の到着（約+0.5秒後）より早い → その窓で押すと overlap ≤ 4 の空振い → 0段の夜明け。帳が開いた瞬間・「もう一夜」を押した直後は、いちばん押したくなる瞬間でもある。

根拠: O-04（A-3 ng）・O-09（C-7 ng）・O-02（A-2 コマ）・O-03（窓の外は 20/20）。反証: 窓の外で押せば必ず置ける。人がこの窓で押すかは未実施（inferred）。

R-2. 0段の夜が全国番付へ送られる

確信度: high — stub SDK で submitScore("main", 0, {title:"宵の口"}) を直接観測。file:// で本物の SDK（standalone）も waiwai:score:main に score 0 を保存。canSubmitScore() は稽古と自動プレイだけを塞ぎ、段数は見ない（SPEC §7-b にも 0 の扱いは無い）。宵あらわしは「0柱の夜は送らない＝番付に0の行を作らない」を明文化している。

因果連鎖: R-1 で0段の夜が起きる → そのまま送信 → 「最高記録を更新」「全国◯位」が0段に対して出る（O-12 のカード）→ 番付に「ナナシ 0段（浄化0）」の行が積まれる。本番ボード（09-01: 8053・8053・1104・300）に 0 はまだ無い。

根拠: O-12（C-10）・O-13（D-11 の localStorage）。受入差分の分類: 要件の欠け（SPEC 未記載）＋シリーズ内の不整合（宵あらわしとの差）。

R-3. 開いてから最初の有効な一手まで、約6秒

確信度: medium — 時間は実測（押せるまで 2.24秒・帳 3.29秒・札の到着 +0.5秒）。ただし「長い」と感じるかは人の実感でしか決まらず、未実施。設計値（SHITSURAE §1: 絵1.2秒＋カード0.7秒＝1.9秒／御霊おとしの実測 1.26秒）より 0.3〜1.0秒遅い。

因果連鎖: 絵→カード（2.2秒）→帳（3.3秒）→札の進入（0.5秒）が直列で、飛ばす口が無い → 初見の待ち時間が積み上がる。R-1 の窓は、この待ちのいちばん最後にある。

根拠: O-01（A-1）・O-02（A-2）・O-04。

R-4. 夜の終わりで、できることが減る

確信度: high（影響は小） — 結果画面では ♪ の上に #overlay が乗っていて押せない（elementFromPoint＝overlay・class 不変）。SDK が読めない経路（Artifact）では #final-rank ごと隠れるため、初めて記録を出した夜でも「最高記録を更新」が出ない。

因果連鎖: 結果札が全画面の覆い（fixed inset:0）で HUD を覆う → 覆いの外の釦が届かない。順位と更新の印が同じ器に入っている → 順位が取れない環境では更新の印まで消える。

根拠: O-11（C-9）・O-08（C-7）。

R-5. 記録の置き場が経路で3通りある（課題ではなく、把握しておく事実）

確信度: low（課題かどうかが未確定） — sdk.js 遮断＝旧4キーに直書き／file:// で本物 SDK＝waiwai:fudakasane_save の束／枠の中＝タウン側。同じ人が Artifact→Pages→枠と渡り歩くと記録は引き継がれない。設計どおり（SPEC §7-a「進捗は共有されない」）であり、ここでは事実として残すに留める。

根拠: O-08・O-10・O-13。

H. 参加者・観点別の寄与

AI-P01（検品担当の代行）1観点のみ。人間の参加者は0名。AI の寄与は「時刻・座標・状態・再現率」の直接観察に限られ、「迷い」「分かりにくさ」は一切測っていない。逆に、人がやらない反復（同じ操作を20回）ができたので、R-1 の窓は人のテストでは偶然にしか出ない再現率が取れた。

I. 結論

公開可否: 公開済みの作品なので「条件付き」——R-2 と R-1 は次の更新で塞ぐ。本家入りの打診が進行中で、先方が最初に触る一手が R-1 の窓に落ちる筋がある。

着手順（捨てる線ではない）: ① R-2（0段の夜は送らない・宵あらわしと同じ規則。1か所の判定で塞げて番付を守る） → ② R-1（札が台に重なるまで入力を解禁しない、または解禁時に札が台に重なる位置から出す。時間割は SHITSURAE §1 の作法で「声を聴いてから」） → ③ R-3（押せるまでの時間と帳を飛ばす口。オーナーの実感待ち） → ④ R-4（結果画面の ♪・更新の印の器の分離） → ⑤ R-5（記録の経路の一覧を README に）。上位に入らなかった「浄化 ×71／×72 の重なり」は次の作業の頭に回す。

次に人で埋めるもの: 帳が開いた瞬間に押すか（R-1 の発生頻度）／約6秒の待ちの実感（R-3）／音の実聴／実枠の番付。

次工程への論点（改善案・分析とは別枠）: R-1 は「解禁を札の到着に合わせる」か「到着前のタップを無視する」かの二択で、後者は SPEC §7 の「開始直後700ms無入力」と同じ作法。R-2 は canSubmitScore() に floors > 0 を足すだけだが、「0段でも自己ベスト更新の印は出すか」は裁定が要る。
